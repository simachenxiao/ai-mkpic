# 物品舱 · 布景

把一台手机（或任何东西）按**真实比例**放进你自己拍的照片里。底图是 `base.jpg`——白色桌面、一包纸巾、一个充电器和一根线；纸巾包和充电器就是画面里的尺子。

零依赖，只用 Node 20+ 自带模块。生图走 OpenAI Images API 兼容的中转：`https://lingsuan.org/v1`，默认模型 `gpt-image-2`。

## 快速开始

```bash
node server.mjs          # 然后打开 http://localhost:8787
```

Windows 直接双击 **`启动.cmd`**（会自动开浏览器）。

参数写在 `.env`：

```ini
IMAGE_BASE_URL=https://lingsuan.org/v1
IMAGE_API_KEY=sk-...
PORT=8787
IMAGE_TIMEOUT_MS=300000
IMAGE_RETRY=2

# 只用一句话：输入物品名称 → 自动写描述 + 估尺寸（可选，不配就退回本地粗估）
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-...
LLM_MODEL=deepseek-flash
LLM_TIMEOUT_MS=90000
```

Key 只存在服务端，前端拿不到。

## 最快的用法：只写物品名称

左栏最上面是「物品名称」：写个「马克杯」，**回车**（或点块内的「生成」/ 顶部的「一键生成」），接下来全自动：

1. **DeepSeek 写好描述 + 估算尺寸**（`/api/describe`）——描述里自动避免俯视/背景/镜头这些词，
   由前端统一拼上固定的「正俯视图：镜头垂直向下 90°、正交投影」那段；
2. 尺寸按**俯视轮廓**估（宽 = 短边、长 = 长边，单位 cm）——不是高度也不是厚度：
   杯子取直径、充电盒取平放时的宽长，直接进「尺寸参照」的目标行；
3. 立刻**开始生图**（一步到底），出来的白底主体自动抠图、按标定尺寸自动摆位、自动存成品。

结果会**缓存**在 `cache/items.json`：同一个名称第二次直接命中、0 元 0 等待。
改了 `server.mjs` 里的系统提示词就把 `ITEM_PROMPT_VERSION` 加一，缓存自动失效。
没有配 `LLM_API_KEY` 或对话模型超时，会自动退回内置的常见物品表（30 项：手机/平板/笔记本/
耳机盒/马克杯/手表/钥匙/眼镜/钱包/遥控器/手链/手镯/戒指/项链/耳环/衣服/包/鞋/帽子/香水/
充电宝/数据线/鼠标/键盘/相机/笔/眼镜盒/零食/保温杯…）；完全不认识的就按 8 × 12 cm 粗估，
描述给「写实外观 + 深色或金属色、不要绿色系」，照样能出图、之后手改。

物品名称只是**快捷入口**：描述和尺寸填进表单后你随时可以改，改完点「生成主体」即可；
也可以跳过名称，直接在「主体描述」里自己写。描述标题旁边的小标会告诉你这行描述从哪来：
「AI 自动 · 8×11 cm」= 模型写的，「已手改」= 你改过，「本地粗估」= 没调通模型用了内置表。
想重新估一遍就点描述下方的「按名称重算描述和尺寸」（会绕过缓存，但**不会**重新生图）。

一条路：**模型只画主体，位置尺寸由标定 + 合成决定**。原图一个像素都不改。

1. 写一句主体描述（默认就是手机），点「生成主体」；
2. 模型画一台**正俯视**的主体（提示词里写死：镜头垂直向下 90°、正交投影、无透视无斜角），
   前端抠图（去白边、去水印、裁到主体）；
3. **自动摆放**：按档案里的标定定尺寸、`planeDeg` 转角度、`squash` 压透视、`slots` 挑空位；
   也可以把「位置」切成 **指定**，直接填 X / Y（像素），点「存为默认」写进档案，以后每次都摆这儿；
4. 不满意就拖一下、调旋转/微调/压缩，或用**橡皮**在压住它的东西（数据线、纸巾包边）上刷一下；
5. 主体一贴上画布就**自动存一张成品**：1920 × 1080 → `output/物品名称_20261108-151734.jpg`；
   调完位置/橡皮想再存一张，点「再存一张」。

**可以连点**：每次点击都是独立请求，互不阻塞。工具条下面会列出「进行中」（带秒表，可单个取消），
先出图的先上画布；出多版时「候选」里能看到每一版，点一下换这一版。失败的任务会留在列表里，可重试或关掉。

**中间图不落盘**：白底主体只在内存里（base64 回传），`output/` 里只有合成好的成品。

结果条会给出文件名，可以「看原图 / 下载 / 在文件夹里看」；历史里点任意一张都是大图预览。

## 抠图：为什么以前有一圈白，现在怎么做的

模型画的是「底色 + 物体 + 一圈软阴影/光晕 + 抗锯齿过渡边」。早先只按亮度阈值切，三个坑：

1. 软阴影的亮度正卡在阈值中间 → 变成半透明白灰像素，贴到深色桌面上就是**一圈白**；
2. 戒指/耳环/杯口这类**被主体包住的内孔**，从四边 flood fill 进不去 → 留成一块死白；
3. 白底上放**白色主体**（白马克杯、AirPods 盒）颜色完全一样，任何阈值都只能二选一地切错。

所以现在**让模型画在纯绿色色键幕布上**（提示词里写死 `chroma key green ≈ #00C853`），
`public/cutout.js` 按幕布做键控。全自动，不需要你用橡皮补刀：

1. **采样四边取背景色**（key）+ 判类型：中性白/灰走一套，绿幕/蓝幕/红幕走另一套；
2. **有色幕布 → 纯色键 + 软遮罩**：按「这个像素有多绿」给 alpha 渐变，
   上下阈值**跟着幕布自己的绿度走**（`SPILL_LO/HI ≈ 幕布绿度 × 0.12 / 0.26`）。
   写死阈值会出事：幕布亮处绿度 117、暗角只有 30 左右，固定阈值会把暗角当成不透明，
   贴到桌上就是**一整块绿色鬼影**；
   不用梯度判据（会在 JPEG 块上抖成锯齿），也不做反预乘（减掉绿只会剩红蓝 → 紫边）；
3. **溢色抑制 + 整体绿偏置校正**：幕布的光会反到主体上，先按像素的“绿嫌疑度”削一遍，
   再量一遍剩下的中位数残差整体削掉——否则深灰布料会一直是墨绿；金/白/暖色完全不动；
4. **内孔**：被主体包住的大片幕布色一样判成孔（戒指的洞、杯子的提手圈都能透过去看桌面）；
   但要求「洞口几乎不碰背景」，白杯身、白 logo 不会被误挖；
5. **中性白/灰底**（老图、或模型没听话）保留原来的 flood fill + Otsu 自适应阈值 + 反预乘那一套；
6. 最后**只保留最大连通块的像素**（不是只裁外框）：角落的水印、`AI生成` 角标、
   小碎块全部清成透明，再裁到主体外框；
7. 出图后还有一道**体检**，不合格就自动重画一次（第二遍换浅灰幕布）：
   - 主体绿色像素 > 20%（幕布把物体吃了）
   - 幕布没铺满整张画面（模型画成了卡片 / 留白边）
   - 抠出来是「整块矩形 + 长直边」（卡片、水印被当成了物体）
   两遍都不合格就**不自动保存**，状态栏直说哪里不对。

## 主体别超出桌面

`scenes/*.json` 里有一张 `surface` 掩膜（96×54 的 base64 位图，就是桌面可落区，自动从底图算的）。
大件物品摆位时会先做九点采样，挑最近的合法落点；**整张桌子都放不下**（比如 26×32 cm 的衣服
放在约 40×27 cm 的桌面上）就等比缩小到能放下为止（最低 55%），状态栏会写「桌面放不下，缩到 85%」。
手动拖到画布外也会被夹回画面内。

另外**模型画的软阴影会被一起切掉**，接地感由合成端自己的径向渐变投影负责——
这样主体的影子方向永远和底图的光向（`scenes/*.json` 里的 `lightDeg`）一致。

## 影调自动匹配

模型是在摄影棚强光下画的主体，你的底图往往偏暗偏暖，直接贴上去就是「一张亮图盖在暗桌上」。
主体落到画布时，自动取它所在区域的底图亮度中位数，给主体算一个亮度系数
（**只压暗不调亮**，而且只压一半、最低 78%——完全按桌面亮度压会把深色衣服压成一团黑），
和底图融在同一个光照里。投影是偏移 13% + 加宽羽化的径向渐变，
贴边那一圈「黑描边」是旧参数留下的，已经改掉。这一步是自动的，
工具条第 3 步那个「亮度」滑块只是万一想手调时的口子，正常不用动它。

## 实测发现（重要）

这个 Key 属于中转站的「生图」分组，只能调 `/api/v1/images/generations`：

- `/api/v1/images/edits`、`/images/edit`、`/v1/images/edits` → 全部 404。
- 在 `generations` 里塞 `image`（data URL / 数组）、改走 multipart → 都不生效。
- 验证方法：底图 + 「把这张照片里的桌面转成卡通，构图不变」，输出是一张和原图毫无关系的插画。
  说明**参考图被丢弃了，这个接口是纯文生图**。
- 当前上游 lingsuan 的 `/v1/models` 有 14 个：`gpt-image-2`（默认）、`gpt-image-2.5-sunburst`、
  `gpt-image-2.6-sunburst`、`gpt-image-2.5-flare`、`gpt-image-1.5`、`gpt-image-1`、`gpt-image-2-firefly` …
  另外还有 `gpt-6-luna` / `gpt-5.6-luna`（对话模型，用来写描述、估尺寸）。
- 早先的 ccsub 分组只有 `gpt-image-1`、`gemini-2.5-flash-image`、`cogview-4` 那几个，且 `openai-image` 常回空图。
